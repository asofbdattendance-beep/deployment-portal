## Frontend structure

- `src/pages/ConsentPage.jsx` — combined Consent & Deploy table for centre roles (debounced auto-save, quota bars with a **department incharge picker** — one incharge per CENTRE × department, chosen from sewadars assigned to that department, saved via `department_incharges` (v12), bulk actions, prev-year columns, custom dept dropdown). Saves are **parallel-safe and field-level**: rows with a saved baseline get a PATCH of only the differing consent fields (`changedConsentFields` — grouped by identical field-set, matched per-row via a quoted PostgREST `or()` filter), brand-new rows are chunked (100) `INSERT`-upserts, removals are batched per centre, and pending edits are flushed on unmount / tab switch / schedule change instead of being dropped. Realtime refreshes coalesce (600 ms debounce), skip the 1500 ms self-echo after own saves (`lastWriteAtRef`), and baseline-sync rows this session did NOT edit — so two open sessions never overwrite each other's work. **Rows the ASO has finalized** (Finalize Deployment) load with a `finalized` flag and lock: consent/dept/bhati/chair controls disabled (`FINAL` pill), bulk actions skip them, `toRemove` never deletes them (DB backstop: v15). **Rows that are `deployed`** (a `deployments` row exists → v32 freeze, which now applies before any centre lock/deadline) are equally locked: read-only dept pill + `DEPLOYED` tag, controls disabled, bulk skips them, persist never writes/deletes them.

- **Scanner decode robustness — stripe localizer, perspective deskew, and a hint-pool bug fix (2026-10-03).** Three changes to the camera decode path plus the first e2e that exercises it. `src/components/scanner/barcodeLocator.js` — Option-B stripe localizer: `locateBarcode(gray, width, height, {minConfidence})` returns `{x,y,width,height,angle,rotation,confidence}` or null, plus `clampBoxTo`/`padBox`. Confidence combines column-profile edge density (local, so a card's straight border can't outvote tilted stripes), anisotropy `axis`, and regularity. Tilt comes from row/column **shift correlation** with parabolic sub-pixel interpolation (`bestShift`/`rowTilt`/`colTilt`/`normAngle`/`measureOrientation`) — not a gradient histogram, which collapses to ~0° for shallow tilts because rasterisation makes `dy` sparse. A transposed retry runs when the primary pass finds nothing, and its box is mapped back with `{...t, x: t.y, ...}` so `regularity`/`peak`/`outsideMean`/`edgesPerRow` survive (dropping them made confidence NaN and silently rejected the box). Contract: **the box is a HINT, never a gate** — a null/low-confidence result must always fall back to full-frame decode. 18 tests. `BarcodeScanner.jsx` wires it as an **aim overlay**, never as a decode gate: `detectionBox` (`src/lib/scannerUtils.js`, 5 tests) maps cornerPoints detect-canvas → video → CSS px under `object-fit: cover`, grows ZXing's 2-point hairline to a ~3.2:1 target and clamps it into the container; the rectangle is published only AFTER the edge reject, repainted at most every 150 ms (while its fade timer is refreshed on every hit so a steady badge doesn't blink), and hides 700 ms after the last detection. When the DECODER is what's failing — so no cornerPoints exist, precisely the "won't catch the badge" case — `locateBarcode` is asked on ≥3 consecutive misses, every 3rd frame, purely to draw the rectangle: it never feeds, narrows or suppresses a decode, so a wrong box can cost a misleading rectangle, never a missed scan. `src/components/scanner/scannerGeometry.js` — perspective deskew via `homography` + `deskewGray`; 27 tests including one proving `deskewGray` beats a plain bbox resize on a synthetic head-end trapezoid (MAE lower both absolutely and vs naive). **Hint-pool bug fixed** (`src/components/scanner/enginePool.js`) — `MultiFormatReader.decode(image, hints)` only calls `setHints` when the hint Map reference differs; the pool called `reader.decode(bitmap)`, passing `undefined`, so `POSSIBLE_FORMATS` and `TRY_HARDER` were wiped on the FIRST frame and every symbology the library ships was attempted every frame while the Native leg stayed tier-filtered. Now two STABLE Maps are built once — `baseHints` (tier list) and `hardHints` (base + `HARD_PATH_2D_FORMATS`, or `opts.hardPathFormats`) — and handed to `decode(bitmap, hints)`, so `setHints` fires only on a deliberate base↔hard switch, and identical sets reuse the SAME object so that switch costs zero rebuilds. `hardPass()` now decodes with `hardHints`. Regression tests in `src/components/scanner/enginePool.hints.test.js` run the REAL @zxing/library (no mock) — red-green verified: with the bug re-introduced all 4 fail, including "a Code 128 frame decoded while configured for code_39 only". 4 tests. `src/lib/barcodeFixtures.js` — the synthetic Code 39 / Code 128 encoders and `render1D`/`render2D`/`invertGray` moved out of `scannerDecode.dataset.test.js` into a shared TEST-ONLY module so both suites use one source of truth. PII rule unchanged: no real badge photo or value is ever committed, every frame is generated in code. `tests/e2e/scanner-robustness.spec.js` — the first e2e that exercises the REAL camera decode path (existing `manualScan()` only fills a text input). An `addInitScript` replaces `getUserMedia` with `canvas.captureStream()` painting a synthetic Code 39 barcode; cases: upright, tilted ~12°, and phone viewport (Pixel 5) — 3 passed. Invariants inherited from `scanner-offline.spec.js`: zero pageerrors via `collectPageErrors`, `resetMock` in `beforeEach`. Known limits: headless Chromium never fires `requestVideoFrameCallback` for a captureStream video, so the spec deletes the rvfc prototype methods and exercises the **rAF fallback** (the production decode path is unchanged); real hardware, permission prompts, torch, tap-to-focus are untested; the decoder under test was the Native BarcodeDetector, not ZXing.

- **Scan popup shows WHO and WHEN (the "my popup isn't showing anything" fix, `useScanHandler` + `ScanResultPopup`).** The popup component was never the bug — it faithfully rendered what it was handed, and `handleScan` shows a popup on every exit. What it was handed for a **fresh badge** (no `dp_attendance_sessions` row in this schedule: the first scan of a visit, or any badge that never scanned before) was identity resolved from `last_out`, which is null — so `displayOf(lastOut)` yielded only a badge number and a clock. `get_scan_state` now returns a third key `sewadar` (`sql/v65_scan_identity.sql`, `docs/context/migrations.md` item 58) read from `get_sewadar_by_badge` + `deployments`, and the handler prefers it (`displayOf(sewadar || lastOut)` / `displayOf(sewadar || open)`, `sewadar ?? null`, with `sewadar: null` explicitly returned by the legacy offline path) — the fallback keeps a not-yet-applied server working exactly as before, and an unknown badge still yields three JSON nulls rather than a throw. Alongside it every choice/result popup carries an event stamp (`eventDate` = `todayStrIST`, `eventTime` = `hmsIST`, the new HH:MM:SS IST sibling of `hhmmIST` in `src/lib/scannerUtils.js`), rendered in `ScanResultPopup` as a **Date** row and a **Time (IN)/(OUT)** row with the direction derived from the moment. The rows are their own block rather than part of the name/centre/dept `<dl>`, deliberately, so an unknown badge still shows when it was scanned; non-directional popups fall back to a bare **Time** and busy/error paths omit the row. The OUT choice keeps `openSince` (the IN that is open) next to the new stamp. **IN time when the moment is IN, OUT time when it is OUT** — a record is not written until the tap, so the stamp is the moment's own time, not the row's. Forwarded through `ScannerPage` / `InchargeScannerPage` / `DeptInchargePage`. Single-valid-direction rule, `choose` camera pause and focus/zoom handling unchanged.
